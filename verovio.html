Task 2: MusicXML and MEI comparison

Three XML element comparisons

These examples come from the exported files. MusicXML is an exchange encoding; MEI is a music encoding framework; Verovio is the software that engraves the data into notation.

1. Note: <note> → <note>

The first note is B4, a semiquaver. MusicXML puts pitch, duration, voice and staff in child elements. Its duration of 1 uses the file’s divisions value of 4 per quarter note. Optional note attributes include id, color and default-x/default-y. In a partwise score its parent is measure; children can include pitch, type, beam and notations. MEI stores this note’s pitch and duration as pname="b", oct="4" and dur="16" attributes, with xml:id and stem.dir. Its immediate parent here is beam inside layer and staff; note can also occur directly in layer or chord and can contain accid or verse. A MusicXML rest is a note containing rest; MEI uses a separate rest element. Consequently, queries and edits must follow different trees, and sounding duration must be interpreted in context.

<note default-x="82.99" default-y="-20">
  <pitch><step>B</step><octave>4</octave></pitch>
  <duration>1</duration><voice>1</voice><type>16th</type>
  <stem>up</stem><staff>1</staff>
  <!-- beam and notations omitted -->
</note>
<note xml:id="l3xgubk" dur.ppq="1" dur="16"
      oct="4" pname="b" stem.dir="up" />

References: MusicXML note; MEI 4 note.

2. Measure: <measure> → <measure>

MusicXML’s opening measure is inside part, with required number="0" and optional implicit="yes" and width attributes. It directly contains notes, attributes, directions and backup events, among other possibilities. MEI’s corresponding measure is inside section, with optional n="0", xml:id and metcon="false". Its children here include staff, mNum and control events; staff contains layer, which groups musical events. MusicXML implicit suppresses the printed number; MEI metcon records whether the measure conforms to the prevailing meter, so these attributes are not synonyms. The exported MEI uses an empty mNum for the pickup’s numbering. Separating staff and layer makes simultaneous musical streams explicit in MEI, whereas MusicXML uses staff/voice children and backup to move through them. Both exports contain 17 measure containers: the pickup, the numbered passage and the X1/X2 split around the repeat.

<part id="P1">
  <measure number="0" implicit="yes" width="187.36">
    <!-- attributes, notes, direction and backup -->
  </measure>
</part>
<section xml:id="u1p8nga7">
  <measure xml:id="s1nf4hxw" metcon="false" n="0">
    <mNum xml:id="b1t0sw0" />
    <staff n="1"><layer n="1"><!-- events --></layer></staff>
    <staff n="2"><layer n="5"><!-- events --></layer></staff>
    <!-- dynamics, tempo, slur and fingering omitted -->
  </measure>
</section>

References: MusicXML measure (partwise); MEI 4 measure.

3. Slur: <slur> → <slur>

MusicXML represents the first slur with separate start and stop elements inside each endpoint note’s notations. Slur is empty; type is required, number distinguishes overlapping slurs, and optional bezier-x/bezier-y or placement describe appearance. MEI places one slur directly inside measure in this export, using startid and endid to reference the endpoint notes’ xml:id values. MEI 4 also permits timestamp endpoints and optional curvedir, bezier or bulge attributes; slur can contain curve children. MusicXML requires matching endpoint markers, while MEI requires resolving references. Renaming a MEI note ID therefore requires updating the slur references. The MusicXML export has 15 slur starts and 15 stops; the MEI has 15 slur elements. This conversion preserves endpoints but omits the first slur’s MusicXML Bézier coordinates, so engraving software recalculates its shape.

<notations>
  <slur type="start" bezier-x="23.945686"
        bezier-y="13.764924" number="1" />
</notations>
<!-- on the endpoint note: -->
<notations><slur type="stop" number="1" /></notations>
<slur xml:id="m8v21cg" startid="#l3xgubk" endid="#j18ftah4" />

References: MusicXML slur; MEI 4 slur.

Conversion and checks

The MuseScore score was exported as uncompressed MusicXML 4.0, imported into the current Verovio editor and exported as MEI on 6 October 2026. The old MusicXML converter redirects to the editor; the file was imported again there to ensure the correct score was used. Both files contain 175 pitched notes, 7 rest events and the same 17 measure labels. The MEI’s slur references resolve to existing notes.
